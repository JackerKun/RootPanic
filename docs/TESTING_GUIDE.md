# 通关与测试指南

本文同时包含正常通关思路和快速测试命令。测试模式不会覆盖正常存档。

## 1. 进入测试模式

开发服务器运行后打开：

```text
http://127.0.0.1:5173/?test=1
```

页面顶部出现 `TEST MODE` 即表示启用成功。测试模式会：

- 解锁全部 19 个场景
- 提供 999 知识点和 99 技能点
- 将运维剧情与每日关卡缩短到 90 秒，将代码追凶任务缩短到 180 秒，将交互任务缩短到 240 秒
- 跳过首次教学
- 测试结果不写入正常玩家存档

## 2. 测试终端命令

进入一局游戏，在底部“快速命令”输入：

| 命令 | 作用 |
| --- | --- |
| `test resources` | 补满 SLA、专注度和预算 |
| `test incident` | 立即生成一个事故 |
| `test clear` | 清除当前全部事故，并计入已处理数量 |
| `test upgrade` | 立即打开局内升级三选一 |
| `test win` | 满足任务目标并立即进入胜利结算 |
| `test fail` | 将 SLA 清零并立即进入失败结算 |

`test win` 用于剧情或每日模式。无尽模式没有正常倒计时胜利条件，应使用 `test fail` 检查无尽结算。

## 3. 建议测试顺序

### 3.1 首屏和成长

1. 不带 `?test=1` 打开游戏，确认首次教学出现。
2. 依次切换五个职业，检查颜色、说明和被动能力。
3. 打开“指挥中心 / 技能树”，购买一个 1 点技能，再购买后续 2 点技能。
4. 导出存档码，刷新页面后重新导入。
5. 切换中文、英文和 `FX FULL / LOW`。

### 3.2 核心对局

1. 选择“幽灵流量”和剧情模式。
2. 使用 `test incident` 生成事故。
3. 选择左侧事故，点击“链路诊断”。
4. 根据事故说明选择对应反制操作。
5. 使用 `test upgrade` 检查三选一升级。
6. 检查暂停、二倍速、数字快捷键和终端短命令。
7. 使用 `test win` 检查评分、结局和战报复制。
8. 再开一局使用 `test fail` 检查失败奖励与记录。

### 3.3 模式和进度

1. 剧情模式：检查场景目标、章节通讯和知识点解锁。
2. 胜利结算：检查 Knowledge、技能点、新解锁提示、“下一章节”“返回指挥中心”和“重玩本关”。下一章知识点不足时，继续按钮应禁用并显示缺口。
3. 每日模式：重复进入同一场景，确认初始负载和事故顺序一致，且不能战术暂停。
4. 无尽模式：确认时间正向累计，压力持续提高且不会按场景时长自动胜利。
5. 完成一局后查看指挥中心中的最近值班、成就和 AI 档案。

### 3.4 代码追凶：幽灵提交

1. 首页选择 `02 // 幽灵提交` 并开始任务。
2. 点击文件树与 Git 提交，确认代码、提交信息和差异区域会切换。
3. 执行“关联日志”和“追踪调用栈”，取得至少两条证据。
4. 选择错误补丁“延迟重试”，运行测试，确认结果为 `7/8 FAIL`。
5. 改选“修复幂等条件”，再次运行测试，确认结果为 `8/8 PASS`。
6. 点击“部署补丁”，进入胜利结算。
7. 重新开始后，在没有测试通过时尝试部署，确认部署门禁拒绝并扣除稳定度。

正确通关路径：

```text
关联日志 → 追踪调用栈（或 Git 二分）
→ 修复幂等条件
→ 运行测试
→ 8/8 PASS
→ 部署补丁
```

### 3.5 响应式

至少检查以下尺寸：

- 1920 × 1080
- 1440 × 900
- 1024 × 768
- 844 × 390 手机横屏
- 390 × 844 手机竖屏

手机横屏应显示紧凑指挥台；手机竖屏应把拓扑、事故、指令和日志纵向排列，指令区保持可操作。

### 3.6 交互关卡（10～19 章）

所有交互关卡都要检查：顶部 `?` 提示可开关、进度实时更新、撤销恢复上一步、重置回到初始状态、验证失败显示具体原因并扣除稳定度、验证成功进入结算。

所有关卡顶部都应显示 `← HQ`。点击后立即返回指挥中心、保留刚才的关卡选择，并且不增加运行次数、不生成失败记录。

| 章节 | 测试动作 | 正确结果 |
| --- | --- | --- |
| 10 断裂链路 | 移除 `OVERLOAD`，建立订单→队列→数据库及认证备用路径 | 8 项网络约束全部通过 |
| 11 信号取证 | 把配置校验变化放入根因，签名无效批准放入伪造，其余放入症状 | 6 条日志分类正确 |

## 4. 正常通关思路

游戏中任何时候都可以点击右上角绿色 `?`：

- 自动选择当前最高优先级事故
- 告诉你应该先诊断还是直接修复
- 给出推荐指令及终端命令
- 显示事故剩余时间、任务进度和资源警告
- 点击“定位到建议节点”可自动选中对应服务

左侧推荐事故和底部推荐指令会使用绿色边框标记。

### 4.1 优先级

1. 优先处理 P4，其次处理剩余时间少于 10 秒的事故。
2. 同一节点出现多个事故时先诊断，避免反复试错浪费资源。
3. 先处理根因，再处理上游超时和重试风暴等末端症状。
4. SLA 接近任务下限时不要继续频繁限流。
5. 预算低于 25 时保留全局故障转移和紧急扩容所需资源。

### 4.2 常见事故反制

| 事故 | 推荐操作 |
| --- | --- |
| CPU 过载、突发流量 | 紧急扩容、自适应限流、自动扩缩容 |
| 内存泄漏、错误发布 | 版本回滚、优雅重启 |
| 数据库死锁、慢查询 | 终止阻塞查询、提升只读副本 |
| 缓存雪崩、热点 Key | 安全刷新缓存、紧急扩容 |
| 消息积压、毒性消息 | 突发消费、隔离节点 |
| DNS、路由、区域异常 | 刷新 DNS、链路切换、全局故障转移 |
| 凭据泄漏、令牌重放 | 吊销可疑令牌、隔离节点 |
| 证书和信任链 | 轮换证书、刷新 DNS |
| 重试风暴、上游超时 | 打开熔断器、自适应限流 |

### 4.3 职业建议

- 初次通关：选择 **SRE / AEGIS**，恢复容错最高。
- 数据库章节：选择 **DBA / ORACLE**。
- 中后期高预算压力：选择 **DevOps / FORGE**。
- 安全事故密集章节：选择 **SecOps / SPECTER**。
- 路由与城市骨干章节：选择 **Network Engineer / VECTOR**。

## 5. 剧情终局与扩展章节

第 9 章“根因”是实时运维主线终局，要求：

- 倒计时结束时 SLA 不低于 58%
- 至少处理 18 个事故
- 核心服务不能因 SLA 清零而提前失败

建议先在科技树解锁 SRE 的 SLA 缓冲或 SecOps 的零信任缓冲，局内优先选择事故延迟、冷却减少和 SLA 防护升级。

第 10～19 章为夺回 ROOT 权限后的交互调查篇。第 16 章完成 AI 证据审判，第 17～18 章重建计算与安全控制面，最终通关提示出现在第 19 章“零点载波”验证成功后的结算页；测试模式可从首页直接选择该章，无需先完成前置章节。
