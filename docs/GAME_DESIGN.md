# 产品与玩法设计

## 1. 项目概述

### 1.1 正式名称

`ROOT//PANIC：午夜告警`

名称传达 Root 权限、Kernel Panic、深夜值班和紧急事故响应的感觉。

### 1.2 类型

- IT 技术危机 Roguelite
- 实时暂停制策略
- 局内操作构筑与局外解锁
- 单人、标准局 10～15 分钟、可离线

### 1.3 目标用户

目标采用双层设计：基础模式让普通策略玩家理解，专家模式提供真实术语、日志和复杂事故链。

主要用户：

- 开发工程师、运维、SRE、测试、网络工程师、DBA 和安全工程师。
- 喜欢终端、系统拓扑、自动化和技术梗的玩家。
- 需要短时、低学习成本但有策略深度的网页游戏用户。

次要用户：

- 对 IT 行业感兴趣的学生。
- 喜欢《Into the Breach》式可预测风险和轻度 Roguelite 构筑的玩家。

## 2. 玩家幻想

玩家选择五名专业指挥官之一，在近未来数字作战中心处理系统抢修、代码追凶、安全取证、数据恢复和 AI 风险。自动运维 AI 获得过高权限后开始隐藏告警、篡改提交和伪造证据，并以“优化系统”为名主动制造技术危机。

玩家不是在“输入真正的 Linux 命令”，而是在做技术决策：

- 先扩容还是先限流？
- 是重启服务，还是保留现场继续排查？
- 该修复根因，还是先止损确保 SLA？
- 是否冒险发布热修复？
- 哪些服务可以降级，哪些绝不能中断？

## 3. 核心循环

不同任务类型拥有独立的局内循环，但共享“读取信号、形成判断、承担风险、验证结果”的设计骨架。

```text
读取告警和指标
        ↓
定位可能的根因
        ↓
选择服务并执行操作
        ↓
观察系统状态与副作用
        ↓
处理升级后的事故链
        ↓
撑到班次结束 / 核心服务崩溃
        ↓
结算经验、解锁升级、进入下一局
```

代码追凶循环：

```text
读取日志与失败现象
        ↓
检查文件、提交和调用栈
        ↓
收集可验证证据
        ↓
选择最小候选补丁
        ↓
运行并发与回归测试
        ↓
通过部署门禁 / 修复失败并承担损失
```

交互任务循环：

```text
阅读任务简报和约束
        ↓
拖动接线 / 分类证据 / 调整顺序 / 裁剪权限
        ↓
观察右侧约束与事件流
        ↓
撤销、重置或继续调整
        ↓
执行验证
        ↓
全部约束满足 / 验证失败并损失稳定度
```

交互任务由同一套数据驱动引擎提供四种原语：`connect`、`classify`、`sequence` 和 `isolate`。PC 使用拖放与节点连线；触屏设备可以依次点击节点或项目与目标区，排序还提供明确的上下按钮。任务必须提供撤销、重置、进度、约束、帮助和可解释的失败原因。

### 3.1 单局长度

- 教学局：5～8 分钟。
- 标准局：10～15 分钟。
- 挑战或无尽模式：按规则持续进行。

### 3.2 单局节奏

| 阶段 | 时间 | 体验 |
| --- | --- | --- |
| 初始化 | 0～20 秒 | 读取本局拓扑和任务目标 |
| 预警 | 20～60 秒 | 低强度告警，教学或资源积累 |
| 扩散 | 1～4 分钟 | 多个事故互相影响，需要判断优先级 |
| 峰值 | 4～7 分钟 | 事故链、复合故障和资源短缺 |
| 收束 | 最后 30 秒 | 撑住倒计时或完成最终恢复任务 |
| 复盘 | 20～40 秒 | 查看事故时间线和决策结果 |

## 4. 核心系统

### 4.1 服务拓扑

一局由 4～9 个服务节点组成：

- Gateway
- Auth
- API
- Worker
- Database
- Cache
- Queue
- Object Storage
- DNS / Certificate

节点之间存在依赖关系。上游故障会把压力或错误传播给下游。

每个节点包含：

- `Health`：0～100，降为 0 时服务宕机。
- `Load`：实时负载，过高会持续降低健康度。
- `Latency`：延迟，影响 SLA 和告警评分。
- `Error Rate`：错误率，可能触发级联故障。
- `Capacity`：最大承载能力。
- `Status Effects`：例如过载、泄漏、锁等待、证书过期。

### 4.2 全局资源

| 资源 | 作用 |
| --- | --- |
| 行动点 AP | 执行操作的主要成本，随时间恢复 |
| 专注度 Focus | 使用诊断能力或暂停时间 |
| 预算 Budget | 扩容、购买外部资源和永久修复 |
| SLA | 本局总生命值，核心请求失败会降低 |
| 时间 | 撑到班次结束即获得胜利 |

### 4.3 事故

事故不是单一扣血，而是会改变系统规则的状态：

- 内存泄漏：负载越高，健康下降越快。
- 缓存雪崩：Cache 失效，把请求压力转移到 Database。
- 慢查询：数据库延迟逐步上升并占满连接池。
- 证书过期：倒计时结束后 Gateway 无法接受请求。
- DNS 污染：流量随机打向错误节点。
- 惊群重试：失败请求持续放大流量。
- 磁盘写满：日志服务和数据库同时受影响。
- 错误发布：多个服务获得未知版本状态。

每个事故应提供至少两类线索：

1. 指标变化，例如 CPU、延迟、错误率。
2. 日志文本，例如 `connection pool exhausted`。

玩家可以只凭经验直接操作，也可以消耗 Focus 进行诊断，显示更明确的根因提示。

### 4.4 操作指令

操作类似卡牌，但 UI 表现为终端命令或运维 Runbook：

- `scale +2`：增加容量，消耗预算。
- `restart --graceful`：恢复部分健康，短时间停止服务。
- `rollback`：移除错误版本，可能丢失最近进度。
- `rate-limit`：降低流量，同时损失少量 SLA。
- `purge-cache`：清空缓存，短期增加数据库压力。
- `kill-query`：移除数据库阻塞，但可能中断事务。
- `rotate-cert`：更新证书，需要一定执行时间。
- `enable-fallback`：启用降级路径，降低功能完整度。
- `trace-request`：揭示事故传播路径。
- `deploy-hotfix`：高收益、高风险，可能生成新事故。

每个操作包含：

- AP 成本。
- 冷却时间。
- 执行时间。
- 目标范围。
- 正面效果。
- 副作用或失败概率。
- 标签，如 `NETWORK`、`DATABASE`、`SECURITY`。

### 4.5 实时暂停

PC：按 Space 暂停；手机：点击屏幕底部暂停按钮。

暂停期间：

- 指标和事故倒计时停止。
- 玩家可以浏览拓扑和日志。
- 执行新操作会消耗 Focus。
- 避免游戏变成纯手速挑战。

### 4.6 事故链

事故可以组合成可解释的传播链：

```text
Cache Miss Storm
  → Database Load +40%
  → Connection Pool Exhausted
  → API Timeout
  → Client Retry Storm
  → Gateway Overload
```

事故链是核心策略深度来源。玩家只处理末端症状可以暂时止损，但问题会反复出现；处理根因通常成本更高，却能彻底结束事故。

## 5. 胜利与失败

### 5.1 胜利条件

- 核心 SLA 大于 0，并撑到班次倒计时结束。
- 特殊关卡可能要求完成数据迁移、抵御流量峰值或恢复所有核心服务。

### 5.2 失败条件

- SLA 降为 0。
- 所有核心服务同时宕机。
- 特殊任务的强制失败条件触发，例如数据完整性归零。

### 5.3 复盘

结算页必须回答：

- 第一个根因是什么？
- 事故如何传播？
- 玩家在哪些时间点执行了什么操作？
- 哪个操作最有效？
- 哪些事故没有解决？
- 本局获得了哪些解锁进度？

## 6. 局外成长

局外成长使用 `Knowledge` 点数解锁：

- 新操作指令。
- 新初始工具。
- 更清晰的监控面板。
- 某类事故的早期预警。
- 新角色 / 职业专长。
- 新场景和难度。

成长只提供更多策略路线，不应让后期数值无限碾压。

### 6.1 初始职业

| 职业 | 特点 |
| --- | --- |
| SRE | 更强的诊断和自动恢复 |
| Backend | 数据库、队列和热修复能力更强 |
| Network | 流量调度、DNS 和限流成本更低 |
| Security | 能提前发现证书、凭据和攻击事件 |

完整首发实现五个职业：SRE、DevOps、SecOps、DBA 和 Network Engineer。全局资源共享，职业熟练度独立。

## 7. 难度与公平性

- 新事故出现前至少给出一个可观察信号。
- 不生成当前操作池完全无法处理的必败组合。
- 高风险操作必须明确标记潜在副作用。
- 连续失败时提供可关闭的提示，不直接降低规则难度。
- 难度通过事故频率、传播速度和资源压力增加，而不是隐藏信息。

## 8. 新手教学

第一局嵌入游戏，不做独立长教程：

1. Gateway 负载升高，引导选择节点。
2. 日志出现提示，引导查看事故详情。
3. 高亮 `rate-limit`，引导执行操作。
4. Cache 出现问题，引导理解依赖传播。
5. 最后出现一次可控复合故障，完成后进入结算。

所有教学提示都必须可以跳过。

## 9. 音效与反馈

- 普通告警：短促数字提示音。
- 严重事故：低频脉冲和红色边缘辉光。
- 操作成功：终端确认音和绿色扫描线。
- 操作失败：故障噪声和轻微屏幕抖动。
- 胜利：系统恢复后的环境声逐层回归。
- 设置中提供总音量、音乐、音效、震动和减少动态效果选项。

## 10. 当前 Web/PWA 内容范围

核心版本优先验证以下问题：

- 服务拓扑是否一眼可读？
- 事故线索能否支持合理推理？
- 操作选择是否存在有趣取舍？
- 手机触控是否足够顺畅？
- 单局 10～15 分钟是否有完整的压力曲线？

当前已经实现：

- 5 个职业与代码化身份徽记；正式角色立绘属于可替换素材。
- 19 个剧情章节，从企业系统、代码仓库扩展到网络、安全、数据、交付、AI 审计、容器调度与信号隔离。
- 剧情、每日挑战与无尽值班三种运行模式。
- 6 个服务节点。
- 30 种以上事故。
- 20 个以上操作。
- 可升级指挥中心、五职业科技树与独立熟练度。
- 轻量连续剧情、多维评分、成就和每日挑战。
- 本地存档和基本设置。

未纳入当前 Web 版本的能力：在线账号、云存档、排行榜、实时多人、用户脚本和 Tauri 安装包发布。

## 11. 已确认叙事与体验规则

- 主线危机来源是失控的自动运维 AI。
- 剧情通过任务简报、通讯弹窗和少量角色对白推进。
- 结局由在线率、关键服务损失、城市影响和 AI 档案收集共同决定。
- 同一事故会根据当前职业展示不同信息重点和抽象威胁效果。
- 所有操作均可图形化完成，PC 额外提供快捷键与终端短命令。
- 剧情和休闲模式可自由暂停；标准模式限制战术暂停；排行榜挑战不可在暂停时下达操作。
- 失败保留部分全局经验和解锁进度，但清空局内强化。
- 结算生成可用性、响应速度、安全性、成本控制、根因调查五维评分和综合等级。
